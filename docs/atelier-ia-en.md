# Use AI to build tools while retaining scientific judgement

Generative AI assistants can support programming, tool development and iterative revision. I distinguish executable code, a valid statistical analysis and an answer to the right research question. Specify the estimand, population, timing and missing-data assumptions before interpreting a result. Human responsibility includes confidentiality, equity and the ability to challenge an output.

## 1. Frame

Purpose, permitted data and expected behaviour.

## 2. Build

Small, understandable changes.

## 3. Challenge

Inspect code, calculations and assumptions separately.

## 4. Account

Document contributions and human decisions.

## Fictional situation · proposed approach

A tool must explain a research finding to managers and the public. The level of delegation depends on whether the task concerns code, analysis or learning.

### Develop a tool

Reasoning : Specify inputs, outputs and edge cases. Review the changes and use synthetic data when appropriate.

Useful output : A specification, version history and an independently calculated reference example.

What to watch : An agent’s access to files and services must fit the authorised task.

### Analyse and interpret

Reasoning : Write the question and assumptions first. Request alternatives and distinguish planned analysis from exploration.

Useful output : An analysis log covering population, variables, estimand, missing data and sensitivity analyses.

What to watch : Producing more can create an illusion of understanding. Preserve methodological diversity and contestability.

### Learn with PAIRR

Reasoning : Start personally, discuss with a peer, use AI as a second critique and justify accepted and rejected suggestions.

Useful output : Successive versions, a reflective note and an appropriate transfer task without assistance.

What to watch : The quality of the final product does not prove learning. State access and assessment rules explicitly.
